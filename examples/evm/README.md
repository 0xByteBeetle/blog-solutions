## Setup, without sending transactions

From the repository root:

```sh
node scripts/check-catalog.mjs
node scripts/check-evm-alignment.mjs
node --test scripts/source-integrity.test.mjs scripts/evm-alignment.test.mjs
```

For builds, provide Node.js 22, Git, npm, real Go (CI uses 1.24.x; modules declare
1.23.10), and Foundry (`forge`, `anvil`, `cast`). A program called `go` is not
necessarily the Go compiler: verify `go version`. The blob transaction package
also imports C-KZG bindings and needs a working CGO/C compiler toolchain.

```sh
node scripts/setup-restored.mjs
```

This downloads reproduction dependencies: OpenZeppelin **5.6.1** from the root
lockfile and forge-std **v1.16.1**, checked at commit
`620536fa5277db4e3fd46772d5cbc1ea0696fb43`. It is not evidence of the original
articles' dependency versions. Solidity compilers may be downloaded by Foundry.
The exact `0.4.25` and `0.8.12` pragmas must not be modernized to make builds pass.
Other sources use ranges, so current Foundry/compiler selection is not fully
pinned. The historical local-run report used Foundry 1.4.4; CI now pins Foundry 1.4.4. Record versions when rerunning.

## Preserved source limitations and supplemental variants

These findings distinguish preserved pedagogical behavior from supplemental fixes.
The original source remains unchanged; see correction tests for demonstrated cases.

- **UUPS:** `MyToken.constructor1` is public and does not reject an already
  initialized instance. It writes supply, sender balance and owner on every call.
  A caller through the proxy can therefore reset ownership; `delegatedOnly` does
  not protect this initializer. The harness never attempts reinitialization.
  The [separate correction](corrections/README.md) now adds an initialization guard
  and adversarial tests without changing the original.
- **RLP:** `RlpDecode` discards the consumed byte count, so a valid first item
  followed by extra bytes is not rejected. `decodeLength` accumulates into `int`
  without overflow checks. Encoder `toInt` narrows signed/unsigned integers to
  platform `int`; large values are not covered by the valid-vector suite. Do not
  treat this educational codec as a strict untrusted-input validator.
- **Permit verifier:** checks recovered signer only. It does not enforce deadline,
  consume nonce, or change token allowance. Those fields being signed is not the
  same as implementing a complete permit authorization policy.
- **Delegation:** invoker extracts a module from the account's delegation marker
  and calls `someModule.call(...)`, rather than calling the delegated account.
  This is module-call behavior; the build check does not prove account-context
  execution. `new bytes(23)` always has length 23, so its length check alone does
  not validate the target's complete code length.
- **Storage validation:** both success tests call `store` without asserting
  `retrieve`; only the revert test checks an explicit expected outcome. Keep
  `DebugStore`'s deliberate failure. The unvalidated `storage` project is a
  distinct original variant and must not be replaced with this guarded version.
- **Diamond:** harness covers adding selectors, not replacement/removal, full
  loupe responses or unauthorized cuts. `LibDiamond.addFunctions` checks nonzero
  facet address but not code length. Educational example, not deployment approval.
- **Minimal proxy:** original factory does not validate implementation code;
  low-level initialization success alone is not an application-level invariant.
  The comment on the creation prologue says 0x37 while the `602d` byte encodes
  a 45-byte (0x2d) returned runtime. Preserve original bytes/comment; suggest an
  explanatory correction separately rather than altering the snapshot.

## Network programs are not an automatic next step

`transaction-types/account/account.go` creates/loads `.key` files and **prints
private keys**. Never run these programs with real accounts or publish their logs.
Keys are intentionally absent and ignored. `legacy-tx`, `eip1559`, `eip2930`,
`eip4844`, and `eip7702` broadcast transactions. Addresses, chain IDs, recipients,
fees, token balances and deployed contracts are historical constants, not settings
validated today. Starting Anvil does not redirect these hardcoded public endpoints.

`personalsign` is offline but still uses the key-printing helper. `eip712` signs
then calls a historical verifier on Amoy; it is not a standalone local unit test.
`eip4844` resolves `./trusted_setup.txt` from the working directory, so its setup
file is in `transaction-types/eip4844/`, not module root. Build success does not
prove blob field encoding, setup/backend selection, fees or acceptance by a node.
No runnable network command is recommended in this guide.
