# Sui Part 2: choosing an object ownership model

Author reference for the [unpublished Substack draft](https://andreyobruchkov1996.substack.com/publish/post/222510085). The article includes every source file, setup command, operation and selected output inline. Readers do not need this repository to follow it.

The current walkthrough uses public Sui Testnet and automatic gas selection. Local Move compilation and seven unit tests accompany the signed Testnet experiments. No gas coins are materialized or split for the current run.

## Five experiments

| Form | Source | Verified behavior |
| --- | --- | --- |
| Address-owned | `move/sources/owned.move` | Alice transfers only the notebook to Bob. Each account then lacks one input. After its capability follows, Bob updates the notebook to 11. |
| Shared | `move/sources/registry.move` | Alice and Bob add entries. Bob's reset enters Move and aborts at the administrator check with code 0. |
| Immutable | `move/sources/rules.move` | Bob supplies the frozen rules as `&Rules`. Supplying them as `&mut Rules` produces `InvalidObjectByMutRef`. |
| Wrapped | `move/sources/case.move` | The notebook is nested inside Bob's address-owned Case. An independent read returns `NOT_FOUND`. Updating through the Case and unpacking restores the original notebook ID with value 12. |
| Party | `move/sources/party_counter.move` | Alice submits two updates before waiting. Both succeed with distinct transaction digests and the counter reaches 2. Bob fails input-owner admission. |

`client/read_object.py` uses native gRPC `LedgerService.GetObject`. It defaults to `fullnode.testnet.sui.io:443`, uses server reflection for protobuf descriptors, and saves the full response. Its printed projection contains runtime owner metadata and the parsed Move value. Missing-object responses are saved with exit status 1.

`client/receipt.py` selects a package or created object ID from saved CLI JSON, or prints status and digest. It uses only Python's standard library.

## Native CLI setup for a fresh author run

With the official CLI on `PATH`, let it create its standard client configuration and accounts:

```bash
sui client --yes new-address ed25519 alice
sui client new-address ed25519 bob
sui client switch --env testnet --address alice
ALICE=$(sui client active-address)
sui client switch --address bob
BOB=$(sui client active-address)
sui client switch --address alice
sui client faucet --address "$ALICE" --url https://faucet.testnet.sui.io
sui client faucet --address "$BOB" --url https://faucet.testnet.sui.io
```

Keep recovery phrases private. Use the generated addresses and IDs from the new run. The CLI selects gas automatically while the commands retain explicit gas budgets. The recorded receipts for all 17 successful executions and both committed failures have empty `gasData.payment` lists.

Initialize the package manifest once, then compile and test the five source files:

```bash
sui move new sui_ownership --path move
sui move build --path move
sui move test --path move --no-lint
```

The manifest generated by `sui move new` needs no manually added Testnet environment. `move/Move.toml.template` preserves the minimal manifest used for the recorded build. The local tests check Move behavior with locally constructed values. The public Testnet experiments check ownership admission and recorded state separately.

Install the Python dependencies before the native reads:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

## Read failures at their actual boundary

- `owned-alice-rejected`, `owned-bob-rejected`, and `party-bob-rejected` fail input-owner checks before Move. The CLI reports the nested cause during automatic gas selection. These errors have no established committed transaction receipt.
- `registry-bob-reset-rejected` is a committed `MoveAbort` with code 0 in `registry::reset`.
- `rules-bob-mutation-rejected` is a committed execution argument error, `InvalidObjectByMutRef`.
- `read-wrapped_child` records `GetObject` returning `NOT_FOUND` while the notebook was inside the Case. A direct update also fails object resolution before execution.
- `case-pack.effects.wrapped` identifies the contained notebook. The CLI `objectChanges` projection calls that transition `deleted`, but the nested UID is retained and unwrapping restores the same notebook identity.

The shared registry's administrator is a Move field, separate from its runtime owner kind. The Case is address-owned and contains the notebook. Wrapping is containment, not an owner enum named `WRAPPED`.
